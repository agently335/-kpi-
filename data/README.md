## 2. 标签定义

`fault` 列为整数标签 0–5，含义如下（沿用原赛题"6 类故障"设定）：

| 标签 | 名称 | 业务含义 | 典型特征形态 |
|---|---|---|---|
| 0 | 正常 | 系统健康运行 | 所有指标处于低位 |
| 1 | CPU 饱和 | CPU 被占满、任务排队 | `cpu_usage` 极高，其他指标基本正常 |
| 2 | 内存泄漏 | 内存持续上涨不释放 | `mem_usage` 高，`error_rate` 升高，CPU/磁盘正常 |
| 3 | 磁盘 IO 瓶颈 | 磁盘读写打满、等待长 | `disk_io_util` 与 `disk_await` 极高 |
| 4 | 网络异常 | 网络延迟高、丢包重传 | `net_latency`、`net_retrans` 极高 |
| 5 | 服务异常/请求堆积 | 请求积压、错误率高 | `error_rate` 高、`req_qps` 下降 |

**训练集标签分布（500 行，刻意不均衡以模拟真实场景）：**

| 标签 | 行数 | 占比 |
|---|---|---|
| 0 正常 | 178 | 35.6% |
| 1 CPU 饱和 | 68 | 13.6% |
| 2 内存泄漏 | 63 | 12.6% |
| 3 磁盘 IO 瓶颈 | 64 | 12.8% |
| 4 网络异常 | 71 | 14.2% |
| 5 服务异常 | 56 | 11.2% |

> ⚠️ **正因为分布不均衡，只看 Accuracy 会被误导**：全部猜"正常"就能拿到 35.6% 的准确率。
> 所以验收必须看 **Macro-F1**（每个类各算一次 F1 再平均），它对小类召回更敏感。

## 4. 107 个特征（`kpi_train_107.csv`）

官方原题为 107 个 KPI 特征，命名为 `feature0` … `feature106`。本数据集沿用该命名，并按语义分成 7 组：

| 组 | 列范围 | 含义 | 组内典型量纲 |
|---|---|---|---|
| cpu | `feature0`–`feature11` | CPU 使用率、负载、上下文切换、运行队列 | %、核数、计数 |
| mem | `feature12`–`feature23` | 内存/缓存使用、缺页、Swap | %、MB、计数 |
| disk | `feature24`–`feature38` | 磁盘利用率、IOPS、吞吐、等待时间 | %、ms、KB/s |
| net | `feature39`–`feature56` | 带宽、延迟、丢包、重传、连接数 | ms、Mbps、计数 |
| req | `feature57`–`feature71` | QPS、并发、队列长度、响应时间 | 次/秒、ms |
| svc | `feature72`–`feature86` | GC 时间、线程数、错误率、超时 | ms、%、计数 |
| misc | `feature87`–`feature106` | 派生指标、聚合统计、其他 | 混合 |

**注意：** 107 维文件里的具体列含义是**为了教学演示而拟定的**，并非官方真实指标定义。若后续获取到官方数据字典，以官方为准，并更新本节。

## 5. 缺失值说明

训练集刻意注入了约 **1.05%** 的随机缺失单元格（562 / 53,500），用于验证：

- 系统能否正确统计并展示缺失率
- 训练前是否有合理的缺失处理（如均值/中位数填补，或剔除）
- 缺失率超过阈值时是否给出警告

预测集的缺失率更低（约 0.5%），因为待预测数据通常质量更好。

## 8. 数据质量自检结果

用 kNN（k=5）在 107 维数据上做快速可分性检查（前 400 行训练 / 后 100 行测试）：

```
混淆矩阵（行=真实，列=预测）
        P0  P1  P2  P3  P4  P5
  T0    31   2   0   1   1   0
  T1     1  14   0   0   0   1
  T2     0   0   7   0   1   1
  T3     1   1   0  11   0   0
  T4     1   0   0   0  15   0
  T5     1   2   0   0   0   8

Accuracy : 0.86
Macro-F1 : 0.85
```

**如何解读这组结果：**

- 数据**不是完全可分**的（没有 100% 准确率），类别之间存在自然重叠 —— 这符合真实场景，也让混淆矩阵有信息量
- 主要混淆发生在 `T2↔P5`、`T0↔P1`、`T3↔P0` 之间，因为这几类故障共享部分指标升高
- 任何随机森林 / 逻辑回归做到 **0.80–0.90 的 Macro-F1 属于正常水平**；若你的模型拿到 **1.00**，大概率是数据泄漏（比如把 `fault` 列误当特征，或训练测试数据重叠）
- 若模型只有 **0.35 左右**，说明它退化成了"全猜正常"，检查特征是否被正确读取
